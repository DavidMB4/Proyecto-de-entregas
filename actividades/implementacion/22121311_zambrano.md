## A — Entorno virtual, proyecto y contenedor

### A1 — Dos opiniones en el equipo

Ana tiene razón en que Docker permite tener un entorno aislado, pero no significa que el entorno virtual sea inútil. El entorno virtual separa las librerías de Python para que no interfieran con otros proyectos, mientras que Docker aisla prácticamente todo el ambiente donde se ejecuta la aplicación.

Luis también tiene parte de razón, ya que con el entorno virtual podemos desarrollar y probar Django localmente. Sin embargo, abrir varias terminales con `runserver` no es una solución para atender muchos usuarios, porque ese servidor es principalmente para desarrollo.

En el curso se utiliza el entorno virtual para trabajar localmente y Docker para ejecutar varias copias de la plataforma con las mismas dependencias. Esto permite distribuir las peticiones con un balanceador y trabajar en un ambiente mas controlado.

### A2 — Se borró la carpeta `.venv`

**a) ¿Perdió su código? ¿Por qué?**

No perdió su código, porque `.venv` solamente contiene las librerías y el entorno de Python. Los archivos del proyecto, como las vistas, modelos y demás código de Django, se encuentran fuera de esa carpeta.

**b) ¿Qué necesita para dejar el proyecto funcionando otra vez y qué papel juega `requirements.txt`?**

Debe crear otro entorno virtual, activarlo e instalar nuevamente las dependencias. El archivo `requirements.txt` facilita esto porque contiene las librerías necesarias y, si está bien configurado, sus versiones.

**c) ¿Qué hace realmente la activación y por qué hay que repetirla en cada terminal nueva?**

La activación no instala Python, solamente configura la terminal para utilizar el Python y las librerías del entorno virtual. Se tiene que repetir porque cada terminal nueva inicia con su propia configuración.

### A3 — ¿Dónde está `/app`?

**a) ¿Dónde existe `/app`? ¿Qué copia exactamente `COPY . .`?**

La carpeta `/app` existe dentro de la imagen y el contenedor de Docker, no necesariamente en nuestra computadora. Se establece con `WORKDIR /app`.

La instrucción `COPY . .` copia los archivos del contexto del proyecto hacia el directorio de trabajo del contenedor, exceptuando lo que indique `.dockerignore`.

**b) ¿Qué problema evita excluir `.venv/` y `db.sqlite3`?**

Excluir `.venv/` evita copiar librerías innecesarias o incompatibles con el ambiente del contenedor, además de aumentar su tamaño.

Excluir `db.sqlite3` evita incluir una base de datos local que puede tener información diferente o desactualizada. Para trabajar con varias copias es mejor utilizar una base de datos compartida como PostgreSQL.
